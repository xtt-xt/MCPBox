# 03 · 工具包与会话

[← 返回 README](../README.md) ｜ [English](en/03-packs-and-sessions.md)

## 为什么要分工具包

工具定义要在**每一轮请求**里重复带给模型。72 个工具全开时，`tools/list` 的正文约 **3.4 万字符**
（按 4 字符 ≈ 1 token 粗算，约 8500 token）；聊 20 轮就是 17 万字符 —— 而且大部分轮次根本用不到那么多工具。

所以把工具分包，`tools/list` 只返回**基础包 + 已激活包**里的工具：

| 包 | 工具数 | 出厂默认 |
|---|---|---|
| `core` 基础 | 4（+5 个包管理工具，默认收起） | **常驻** |
| `file.read` 文件读取 | 8 | 开 |
| `memory` 记忆库 | 10 | 开 |
| `file.write` 文件写入 | 9 | 关 |
| `shell` 命令与自定义工具 | 8 | 关 |
| `ui` UI 自动化 | 8 | 关 |
| `browser` 浏览器 | 18 | 关 |
| `my.tools` 我的工具 | 动态（跟随自定义工具） | 关 |

**出厂默认 22 个工具**（实测：该配置下 `tools/list` 正文约 9.6 千字符），约为全量的三成 —— **比全带上省约七成**。

包是**你自己的长期设置**：在「**权限 → 工具包**」里勾好，AI 看到什么就用什么，完全不知道有包这回事。
包只影响 `tools/list` 的**可见性**，不影响 `tools/call` —— 直接按名字调用任何存在的工具仍然允许
（照常走权限矩阵）。这样即使客户端不支持 `notifications/tools/list_changed`，也不会出现「激活了却调不到」的死锁。

> **⚠️ 改完要重连才生效**
> 主流 MCP 客户端**只在连接时拉一次工具列表**，之后不会再拉（服务端也没法通知它刷新）。
> 所以改完工具包后，需要重新连接 MCP 服务（或重启 App），AI 才会看到变化。

## 自建工具包

- App 里：「权限 → 工具包 → ＋ 新建工具包」进入整页编辑（搜索框 + 勾选列表 + 底部保存）。
- 让 AI 建：打开「让 AI 自己开关包」后，AI 可以用 `manage_pack` 新建 / 修改 / 删除自定义包。
- 包名会显示给 AI 看，所以说明里最好写清「**什么时候该激活这个包**」。
- 内置包不能改名 / 删除；`core` 常驻且不可停用。

> 已知缺口：现有工具包目前**没有编辑入口** —— 工具包行点击是「开 / 关这个包」，
> 旁边只有删除按钮。要改已有包的内容，暂时得删掉重建（或让 AI 用 `manage_pack` 改）。

## 可选：让 AI 自己开关包（默认关）

「权限 → 工具包」里有这个开关。打开后 AI 能看到并调用 5 个包管理工具
（`list_packs` / `activate_pack` / `deactivate_pack` / `reset_packs` / `manage_pack`），
`initialize` 的说明里也会列出还没激活的包和它们的用途。

**为什么不默认开**：实测主流客户端只在连接时拉一次工具列表，而客户端还会按自己缓存的工具表
**拦截调用** —— 所以 AI 激活了一个包，这一轮、下一轮都调不到里面的工具，白白浪费好几轮对话。
默认关掉，既省下那 5 个工具的 token，也不给 AI 挖坑。

## 会话隔离：`/mcp/p/<名字>`

MCP 协议层面**无法感知「AI 开了新对话」**——客户端只在启动时 `initialize` 一次，之后所有对话共用同一条连接。
所以用请求路径来区分：

```
/mcp            → 默认会话
/mcp/p/编码     → 编码场景（可以自己激活 file.write + shell）
/mcp/p/写作     → 写作场景（只要 memory）
```

- 每个会话各自记着「激活了哪些包」，互不干扰。
- 状态存在 `filesDir/profiles/<名字>.json`，重启 App 也保留。
- 在权限页可以选会话、重置、删除（每行右边的垃圾桶；`default` 是兜底会话，不给删）。

**TTL 兜底**（默认开，30 分钟）：超过这段时间没请求，会话就回到默认包集，
这样「隔一阵开新对话」拿到的也是干净状态。位置：设置 → AI 与工具 →「会话状态自动重置」。
