## 架构

```
mcpcore/   纯 Kotlin/JVM，零 Android 依赖：HTTP 服务器、MCP 协议、工具实现、
           权限矩阵、文件桥、文件网关、静态托管（可单独跑、可测）
harness/   端到端测试：真起一个 HTTP 服务器，用真请求打所有工具与安全策略
app/       Android 层：Compose UI、前台服务、审批悬浮窗 / 通知、Shizuku 接入、终端、内置浏览器
```

分层的意义：**拦截逻辑全在 `mcpcore`**，所以能被端到端测试覆盖，也不依赖 Android 运行时。

- `mcpcore` 不认识 Android，宿主能力（通知、剪贴板、root / Shizuku、WebView）通过接口注入。
- `harness` 里跑的是**真服务器 + 真 HTTP 请求**，不是 mock：拦截顺序、鉴权、权限矩阵、审批、静态托管、浏览器（假 WebView 桥）都在这一层验。

## 构建

```bash
# 端到端测试（633 项断言，真起服务器）
./gradlew :harness:e2e

# 构建
./gradlew :app:assembleDebug        # 调试包
./gradlew :app:assembleRelease      # 正式包（无密钥时产出未签名 APK）
```

| 项 | 值 |
|---|---|
| JDK | 17 |
| compileSdk / targetSdk | 35 |
| minSdk | 26 |
| Gradle | 仓库自带 wrapper（8.13） |
| AGP / Kotlin | 8.7.3 / 2.1.0 |
| 模块 | `mcpcore` + `harness` + `app` |
| release APK 体积 | 约 2.7MB |

## 签名

签名信息**不入库**（`keystore/` 在 `.gitignore` 里）。构建时按环境变量读取：

| 环境变量 | 说明 |
|---|---|
| `KEYSTORE_PATH` | 密钥路径，默认 `keystore/release.keystore` |
| `KEYSTORE_PASSWORD` | keystore 密码 |
| `KEY_ALIAS` | 别名 |
| `KEY_PASSWORD` | 别名密码 |

**没有密钥也能构建** —— 只是 release 包不会被签名。

## 版本号与发版

版本号格式 **`v<发布版本>-<核心版本>`**（例：`v1.2.2-126`）：

| 部分 | 例子 | 什么时候变 |
|---|---|---|
| 发布版本 | `1.2.2` | **只在正式发版时**递增 |
| 核心版本 | `126` | **每次构建都 +1**，等于 `versionCode` |

好处：`versionCode` 恒定递增 → 升级安装永远不冲突；`versionName` 只在发版时动 → 用户看到的版本有意义。

日常发版一条龙（`tools/release.sh` 会构建、上传 APK 到手机、commit + push）：

```bash
tools/release.sh                # 日常构建：核心版本 +1
tools/release.sh 1.2.2 "说明"    # 发行版：版本名改成 1.2.2、核心版本 +1、打 tag、push --follow-tags
```

发版前先写 CHANGELOG 的 `## v1.2.2 · 日期` 段落（发行版那段**中英对照**，日常构建段只写中文），
标题必须以 `## v1.2.2` 开头 —— CI 靠它抓发布说明。

## GitHub Actions

[`.github/workflows/build.yml`](../.github/workflows/build.yml) 在推送到 `main`、发 PR 或打 `v*` 标签时触发：

1. 还原签名密钥（`KEYSTORE_BASE64`，没有就跳过 → 产出未签名 APK）
2. 跑端到端测试 `:harness:e2e`
3. 构建 `assembleRelease` + `assembleDebug`，并校验签名
4. 整理产物：`MCPBox-v<版本>-<核心版本>-release.apk` / `-debug.apk` / `-source.zip`
   （源码 zip 用 `git archive` 生成 —— GPL-3.0 要求分发二进制时提供对应源码）
5. 上传 Artifacts（保留 30 天）
6. **打 `v*` 标签时**：从 CHANGELOG 抽对应段落当发布说明，创建 Release 并附上三个附件

想让 CI 产出**已签名**的 APK，在仓库 **Settings → Secrets and variables → Actions** 里加四个 Secret：
`KEYSTORE_BASE64`（本机 `base64 -w0 keystore/release.keystore` 后整段粘贴）、`KEYSTORE_PASSWORD`、
`KEY_ALIAS`、`KEY_PASSWORD`。
