# 06 · 内置浏览器与 UI 自动化

## 内置浏览器（`browser` 包，18 个工具，**不需要 Root / Shizuku**）

App 自己带一个 WebView，AI 可以用它上网：打开网页、读正文与可交互元素、点击 / 填表 / 滚页 / 等元素、
执行 JS、网页截图、多页面管理、用各平台搜索、把网页存成文件、下载链接。
18 个工具逐个说明见 [01 工具清单](01-工具清单.md#browser--内置浏览器18-个出厂关不需要-root)。

### 安全与默认值

| 项 | 默认 | 说明 |
|---|---|---|
| 内网 / localhost | **禁止** | 防止网页脚本反过来去调本机的 MCP 端口；可在设置 → 浏览器里放开 |
| 最多页面数 | **5** | 超出后要先关掉一些 |
| 默认搜索引擎 | **Bing** | 可选必应 / 百度 / Google / DuckDuckGo / 知乎 / 微博 / B 站 / GitHub / 维基… |
| 全局身份（UA） | **手机版** | 单页可覆盖成桌面版 |
| 登录态 | 与系统浏览器**隔离** | cookie / 缓存只属于 MCPBox，不碰你日常浏览器的账号 |
| 审批 | **每个动作都问** | 权限键 `browser.control` 默认「询问」（可在权限页调整） |

### 「按页面」管 cookie 与身份

每个页面可以有自己的 User-Agent 和 cookie：

- `browser_open` / `browser_navigate` 直接带 `ua`（`mobile` / `android` = 手机版，`desktop` / `windows` = 桌面版）
  与 `cookies`（加载前先写进去，所以**第一个请求就带登录态**）。
- `browser_storage` 支持 `page` 参数：不给 `url` 时目标就是那个页面的网址。
  动作有 `get_cookies` / `set_cookie`（支持多行、一行多条）/ `clear_site_cookies`（只清这个站点）/
  `clear_cookies`（清全部）/ `clear_cache` / `get_ua` / `set_ua`。
- 全局身份改了以后，**已经设过单页覆盖的页面不受影响**。

### 悬浮球与悬浮窗

有页面打开时，手机上会出现一个悬浮球：点开是带描边的面板，按钮一行五个 ——
**暂停 AI / 刷新页面 / 关闭本页 / 全部关闭 / 收起**。

- 「暂停 AI」只拦 AI 的动作；用户手动「刷新页面」不受暂停限制（自己接管时不该被自己拦住）。
- 面板可以拖动，点开就能看页面、切页面、自己接管操作。

### 已知限制

| 限制 | 原因 |
|---|---|
| `clear_site_cookies` 删不掉 **HttpOnly** 的 cookie | Chromium 不把这类 cookie 交给 Java 层 |
| 单页 UA 覆盖改不了 **client hints** | 实测 `httpbin` 回显的 `User-Agent` 是自定义串，但 `Sec-CH-UA` 仍是 Android WebView |

### 读内容时的小约定

`browser_content` / `browser_search` / `browser_save` 默认**先自动滚到底**再读（`auto_scroll=false` 可关，
`scroll_rounds` 控制滚几屏）—— 很多站点要滚了才加载内容；滚完停在底部，不会自己回顶。

## UI 自动化（`ui` 包，8 个工具，**需要 Root 或 Shizuku**）

把手机屏幕当接口：截屏看画面、读界面结构（控件树 + 绝对坐标）、模拟点击 / 滑动 / 输入 / 按键、
启动应用、等元素出现。工具清单见 [01 工具清单](01-工具清单.md#ui--ui-自动化8-个出厂关需-root--shizuku)。

- **为什么要特权**：截屏、读控件树、注入点击都是系统权限，应用自身 UID 做不到。
- **后端自动回退**：读界面结构时会在所有可用的特权后端之间自动回退（**root 优先**），
  换后端成功时日志里留一条「UI 后端回退」。
- **输入中文**：`ui_input` 会自动走「写剪贴板 → 模拟粘贴」。
- **别死重试**：报 `idle state` 时直接放弃重试（再试也是同样结果）。
- **权限键**：`ui.control`（默认「询问」）。

> 真机上的 UI 自动化比较慢，且受当前前台应用影响 —— 建议先 `ui_screenshot` / `ui_dump`
> 看清当前画面和坐标，再决定点哪里。
