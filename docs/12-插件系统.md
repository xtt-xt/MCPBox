# 12 · 插件系统（设计草案）

> 状态：**草案，尚未实现**。本文定义插件包的格式、运行时、权限与界面，实现时以本文为准；
> 实现过程中如有偏离，回来改这一页。

插件 = 一个目录，里面有 manifest 和若干脚本。装进 MCPBox 之后，它可以做两类事：

- **工具类**：给 AI 提供 MCP 工具，每次调用过审批；
- **服务类**：在 MCPBox 的端口上开自己的 HTTP 路由，让别的程序直接连进来。

---

## 1 目标与非目标

### 1.1 两个必须先跑通的场景

**手机上的免费模型网关。** 把 dsh 插件 `dsh-our-free-model` 的匿名免费通道（OpenCode Zen、
Kilo 公共网关）搬到手机上，以 MCPBox 插件的形式对外提供 OpenAI 兼容接口。开启后，
RikkaHub、curl 这类客户端填本地地址 + 插件生成的 Key 就能直接调用。第一阶段只做匿名通道，
要登录态和 GitHub 校验的渠道以后再说。

**电脑与手机之间的文件桥。** 手机端插件提供一套文件 API，电脑上的 dsh 插件（Node 写的
独立项目）连过来，做侧边栏面板：显示手机目录、把文件引用进对话、直接编辑写回、
从电脑往手机传文件。传输走局域网或 Tailscale，鉴权用插件自己的 Key。

这两个场景决定了插件不能只是「给 AI 加工具」，必须能对外提供服务（第 3 节）。

### 1.2 能力清单

- 一个插件带一组工具，每个工具自己的参数
- 插件有自己的设置，工具运行时读取
- 插件可以注册自己的 HTTP 路由，带独立 Key 与流式响应
- 插件可以有自己的页面（声明式或 HTML）
- 插件能在设置页的指定位置注入卡片与开关
- 插件可以声明自己要求的 MCPBox 版本与插件 API 版本
- 插件可以常驻：定时任务、启动时执行、监听文件变化
- 一个插件一个工具包，默认关闭，不占 AI 的 token
- 与现有自定义工具兼容，老的 `custom_tools.json` 平滑迁移

### 1.3 不做

- 插件不能改 App 自己的界面和导航
- 不做免安装的远程代码执行；代码必须随包安装
- 工具类调用不绕过审批，任何插件都不绕过 `PathSandbox`
- 一期不引入独立进程，插件与主服务同进程，靠异常捕获与超时隔离
- 不提供 WebSocket 升级，需要推送的地方用 SSE

## 2 为什么不是在自定义工具上直接加字段

自定义工具（`custom_tools.json`）已经具备「单工具插件」的雏形：名字、标题、说明、
参数表、权限键、命令模板、导入导出、`my.tools` 包。缺少的是：

| 缺口 | 插件系统怎么补 |
|---|---|
| 一个工具只有一条命令 | `plugin.json` 里声明多工具，每个工具一个脚本文件 |
| 没有自己的配置 | `settings` 声明 + `config.json` 存储 + `ctx.settings` API |
| 没有生命周期 | 目录即单位，安装/停用/升级/卸载都以目录为粒度 |
| 只有 shell 一种实现 | `kind` 扩成 `shell` / `js` / `python` |
| 没有界面 | 声明式页面区块 + 可选 HTML 页面 |
| 不能后台运行 | 由前台服务托管调度器与事件 |
| 不能对外提供服务 | `http.routes` 声明路由，挂进现有的 `HttpServer` |

所以不推翻自定义工具，而是把它当作 `kind: "shell"` 的一种插件工具：
旧数据在首次启动时迁移进内置插件 `my.tools`，`create_custom_tool` 等工具照常可用。

## 3 两类插件

| | 工具类 | 服务类 |
|---|---|---|
| 谁在用 | AI 客户端通过 MCP 调用 | 外部程序直接连 HTTP |
| 粒度 | 一次工具调用 | 一个 endpoint |
| 授权 | 每次过 `ApprovalCenter` | **安装时授权 + 插件独立 Key** |
| 频率 | 低，弹窗可接受 | 高频（每个 token 一次），弹窗不可行 |
| 典型例子 | 查天气、整理文件 | 模型网关、文件桥 |

服务类不走逐次审批，是需求本身决定的：模型网关每个 token 都要经过，审批弹窗会让它不可用。
这不是放松安全，而是把闸门挪到别处——安装时把能力摆在用户面前，装完用独立 Key 守门。
现有 SSH 服务就是这个模型：唯一的闸门是「允许执行命令」这个开关，具体命令不逐条审批。

一个插件可以同时是两类：文件桥既有 AI 可调的工具，也有给电脑用的 HTTP 接口。

---

## 4 包结构

插件装在应用私有目录 `files/plugins/<插件 id>/`：

```
files/plugins/<id>/
  plugin.json          必需，manifest
  tools/               可选，工具脚本
    <tool>.js
  api/                 可选，HTTP 路由处理脚本
    <handler>.js
  web/                 可选，插件自己的页面与静态资源
    index.html
  data/                运行时可写，插件自己的数据
  logs/                运行日志（环形，最多 500 条）
```

- 插件 id 一旦安装不可更改；改 id 视为另一个插件。
- 插件目录之外的文件只能通过 `ctx.fs` 访问，仍受 `PathSandbox` 与权限矩阵约束。
- `data/` 是插件唯一默认可写的目录。

## 5 plugin.json

### 5.1 顶层字段

| 字段 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `id` | string | 是 | `[a-z][a-z0-9_]{1,31}`，全局唯一 |
| `name` | string | 是 | 显示名，最长 40 字 |
| `version` | string | 是 | 形如 `1.0.0`，用于升级比较 |
| `author` | string | 否 | 作者 |
| `description` | string | 是 | 一句话说明，显示在列表里，最长 200 字 |
| `homepage` | string | 否 | 项目页或说明页 |
| `permissions` | string[] | 否 | 声明需要的能力，见第 12 节 |
| `settings` | object[] | 否 | 设置项声明，见 5.2 |
| `tools` | object[] | 否 | 工具声明，见 5.3 |
| `http` | object | 否 | HTTP 路由与 Key，见 5.4 |
| `ui` | object | 否 | 页面声明，见第 10 节 |
| `background` | object | 否 | 后台任务声明，见第 11 节 |
| `requires` | object | 否 | 版本要求，见 5.5 |

### 5.2 settings

```json
{ "key": "api_base", "type": "string", "title": "接口地址",
  "description": "不带结尾斜杠", "default": "https://api.example.com" }
```

| type | 界面控件 | 存储 |
|---|---|---|
| `string` | 文本框 | 字符串 |
| `secret` | 打码文本框 + 显示按钮 | 字符串，默认不进导出与备份 |
| `integer` | 数字输入 | 整数 |
| `number` | 数字输入 | 小数 |
| `boolean` | 开关 | 布尔 |
| `enum` | 下拉菜单 | 字符串，必须在 `options` 里 |

`key` 只能是 `[a-z][a-z0-9_]*`。设置项由 App 自动渲染成原生控件，插件作者不写 UI。
设置值存 `files/plugins/<id>/config.json`，由插件页或 `ctx.settings.set` 写入。

### 5.3 tools

```json
{
  "name": "forecast",
  "title": "查天气",
  "description": "按城市名查未来几天天气。给 AI 看的说明，写清什么时候用。",
  "file": "tools/forecast.js",
  "timeoutMs": 20000,
  "params": [
    { "name": "city", "type": "string", "required": true, "description": "城市名" },
    { "name": "days", "type": "integer", "default": "3", "description": "天数，1~7" }
  ]
}
```

- `name` 在插件内唯一，`[a-z][a-z0-9_]{0,40}`。
- 对外注册名是 `<插件id>__<name>`，总长不超过 64；冲突的安装直接失败。
- 参数类型：`string` / `integer` / `number` / `boolean` / `enum`（`enum` 需带 `options`）。
- `timeoutMs` 上限 300000，默认 30000。
- 工具的权限不在工具级写死，而由脚本实际调用的 host API 决定（读文件走 `fs.read`、
  跑命令走 `shell.exec`……）。工具级四态策略照旧可以在工具权限页单独设。

### 5.4 http

```json
"http": {
  "enabledByDefault": false,
  "bind": "loopback",
  "routes": [
    { "path": "/v1/models",           "handler": "api.models",  "methods": ["GET"],  "auth": "key" },
    { "path": "/v1/chat/completions", "handler": "api.chat",    "methods": ["POST"], "auth": "key", "stream": true }
  ],
  "key": { "label": "API Key", "prefix": "sk-" }
}
```

| 字段 | 说明 |
|---|---|
| `bind` | `loopback`（只监听 127.0.0.1，默认）/ `lan`（绑 0.0.0.0，安装时明确告知风险） |
| `routes[].path` | 必须以 `/` 开头；按前缀匹配，长前缀优先 |
| `routes[].auth` | `key`（插件 Key）/ `none`（仅允许 loopback 时可用） |
| `routes[].stream` | 是否允许该路由升级为 chunked 流式响应 |
| `key.prefix` | 生成 Key 时的前缀，便于用户识别（如 `sk-`） |

**保留前缀。** 这些路径不允许插件占用，安装时校验，冲突直接失败：

```
/mcp  /sse  /messages  /api/*  /web  /upload  /download  /console
```

除此之外任意根级前缀都可以，包括 `/v1/*`——因为 MCPBox 自己不用它，
这样客户端填的 base URL 就是最标准的 `http://127.0.0.1:8720/v1`。

### 5.5 requires（版本要求）

```json
"requires": { "mcpbox": ">=1.7.0", "api": 1 }
```

| 字段 | 说明 |
|---|---|
| `mcpbox` | 要求的 MCPBox 版本，按 versionName 做语义化比较 |
| `api` | 插件使用的插件 API 版本（整数） |

`mcpbox` 支持 `>=1.7.0`、`^1.7.0`（同主版本）、`~1.7.0`（同次版本）、`1.7.0`（精确）四种写法。
不写 `requires` 等于不限制，为兼容早期插件。

| 时机 | 不满足时 |
|---|---|
| 安装 | 拒绝，正文写明「需要 MCPBox 1.7.0 及以上，当前 1.5.0」 |
| App 升级后 | 插件进入「不兼容」：禁用、路由关闭、列表标黄、副标题写明要求；**不删数据** |
| App 降级 | 同上 |
| 插件 `api` 超出 App 支持的档位 | 同上，副标题写「插件 API 版本不兼容」 |

比较用 versionName（`1.5.0` 这种），不用 versionCode——后者只是构建递增计数，跨分支不可比。
App 侧的当前版本从 `ServerMeta.fullVersion` 里解析出发布版本那一段。

## 6 运行时

### 6.1 分层

```
mcpcore
  PluginManifest.kt   解析与校验 plugin.json
  PluginStore.kt      扫描/安装/停用/卸载/迁移，维护插件列表
  PluginRuntime.kt    接口：eval(code, ctx) -> JSON
  PluginHost.kt       ctx 的实现：把 host API 转成现有的工具/文件/shell 能力
  PluginRouter.kt     插件路由表与分派，挂在 McpServer.dispatch 之前
app
  JsPluginRuntime     quickjs-kt 实现
  PyPluginRuntime     Chaquopy 实现（后期）
harness
  FakePluginRuntime   记录调用、返回固定结果，测流程不测引擎
```

`mcpcore` 仍然不依赖 Android；引擎实现由 App 通过接口注入。harness 用假运行时把
「安装 → 注册 → 调用 → 审批 → 卸载」整条链路跑通，再单独测 manifest 校验与迁移。

### 6.2 脚本契约

工具脚本默认导出一个对象：

```js
export default {
  async run(ctx) {
    const base = ctx.settings.get("api_base")
    const res = await ctx.http.get(`${base}/v1/forecast?city=${encodeURIComponent(ctx.args.city)}`)
    if (res.status !== 200) return { error: `接口返回 ${res.status}` }
    return (await res.json()).days.map(d => `${d.date}  ${d.low}~${d.high}`).join("\n")
  }
}
```

路由脚本导出一个处理函数：

```js
// api/chat.js
export default async function (ctx, req) {
  const body = await req.json()
  const upstream = await ctx.http.post("https://upstream.example/v1/chat/completions", {
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(body)
  })
  if (body.stream) {
    // 逐帧转发上游 SSE
    for await (const chunk of upstream.sse()) ctx.sse.write(chunk)
    return ctx.sse.close()
  }
  return req.respond(200, "application/json", await upstream.text())
}
```

- 返回值：字符串直接作为工具结果；`{ error }` 表示失败；路由侧用 `req.respond` 或 `ctx.sse`。
- 抛异常会被宿主捕获，转成错误响应，不影响服务器。
- 一期不提供跨文件 `import`；之后支持 `lib/` 相对导入。

### 6.3 host API

| API | 说明 | 权限 |
|---|---|---|
| `ctx.args` | 已填默认值的参数对象 | — |
| `ctx.settings.get/set` | 读写插件设置 | 写设置不审批 |
| `ctx.fs.read/write/list/remove` | 路径经 `PathSandbox` | `fs.read` / `fs.write` / `fs.delete` |
| `ctx.shell.run(command, { cwd, timeoutMs })` | 复用三种后端 | `shell.exec` |
| `ctx.http.get/post/fetch(url, options)` | http/https；返回 `{ status, headers, text(), json(), sse() }` | `network` |
| `ctx.sse.write/comment/close` | 仅路由脚本可用，封装 `Exchange.openSse` | `http.serve` |
| `ctx.tools.call(name, args)` | 调用已存在的工具（内置或插件），走它自己的权限 | 被调工具决定 |
| `ctx.log(level, message)` | 写插件日志 | — |
| `ctx.plugin` | `{ id, version, dataDir }` | — |

路由脚本的 `req`：

| 成员 | 说明 |
|---|---|
| `req.method` / `req.path` / `req.query` / `req.headers` | 请求信息 |
| `req.bodyText()` / `req.json()` | 请求体（已按 Content-Length 或 chunked 读全） |
| `req.remote` | 远端地址，用于绑 loopback 时的额外判断 |
| `req.respond(status, contentType, body)` | 一次性响应 |
| `ctx.sse` | 流式响应，见 8.3 |

### 6.4 限制

| 项 | 值 | 说明 |
|---|---|---|
| 单次工具调用超时 | 工具声明，默认 30s，上限 5min | QuickJS 支持中断求值 |
| 路由请求超时 | 120s（流式按空闲时间算） | 模型网关的长回答够用 |
| 并发 | 每插件 1 个工具任务；路由请求按线程池 | 队列上限 8 |
| 内存 | 引擎默认上限 | quickjs-kt 的内存上限能力待实测 |
| 日志 | 每插件 500 条环形 | 超过丢弃最旧 |
| 出网 | 只允许 http/https；内网地址默认拦截 | 与内置浏览器同一口径 |

## 7 工具注册与工具包

- 插件工具在 `McpServer.builtinTools` 组装之后追加，与自定义工具同一个位置（每次请求重新生成，改完即生效）。
- 每个插件自动生成一个工具包：

```kotlin
ToolPack(
    id = "plugin.<插件id>",
    title = "插件 · <name>",
    description = "<插件 description>（由插件提供）",
    tools = 该插件的全部工具名,
    builtin = true,
    defaultActive = false
)
```

- 包默认关闭，不增加默认 token。
- 插件停用 = 工具从注册表消失 + 包从列表消失 + 路由关闭。
- `tools/call` 与内置工具同一口径：不按包过滤，拦人的是权限与工具级策略。
- 只有服务、没有工具的插件（例如纯网关）不生成工具包，只出现在插件列表里。

## 8 服务类插件：路由、Key 与流式

### 8.1 分派顺序

`McpServer.dispatch` 的顺序是「仅本机 → 网页密码 → 内置路由 → 插件路由 → 404」。
插件路由插在内置路由都认不出来之后：

```
① 内置路由（/mcp、/sse、/api/*、/web、/upload、/download、/console、/health）
② 插件路由（按声明路径，最长匹配优先）
③ 404
```

- 命中插件路径的请求**不经过** `checkAuth`（MCPBox 的令牌）与网页登录跳转，
  用插件自己的 Key。客户端填的是 `sk-xxx`，不是访问令牌，两套凭据不能混。
- 全局的「仅本机访问」（`consoleLocalOnly`）仍然生效，插件路由不绕过它。
- 路径匹配：精确相等，或**尾部 `*` 前缀通配**（`/v1/*` 接住 `/v1/` 下面全部，
  但不含 `/v1` 本身）。多条命中时取 `path` 最长的那条。

### 8.2 插件 Key

- 每个服务类插件一把独立 Key，安装时生成，前缀取 `http.key.prefix`（如 `sk-`）。
- 存在 `config.json` 的 `__key`，插件页显示时打码，点「显示」才展开；「复制」永远复制明文。
- 鉴权认两种头：`Authorization: Bearer <key>` 与 `X-API-Key: <key>`。
- 比较用常量时间；不对返回 401，正文只有一句 `{"error":"Key 不对"}`。
- 换 Key 后旧 Key 立刻失效，并且这个插件开着的流式连接全部关闭。

### 8.3 对外服务的两层开关

| 字段 | 含义 |
|---|---|
| `__httpEnabled` | 用户在插件页上的「对外服务」开关 |
| `__httpGranted` | 用户**确认过**可以对外提供服务（打开开关时自动记下） |

`InstalledPlugin.serving` = 插件生效 + 开关打开 + 授权过。三者缺一，`routes()` 返回空，
路径回到「没有插件认领」→ 404。装完默认不授权，避免装上就对外开端口。

`bind` 决定接不接受非本机请求：

| 值 | 绑定 | 说明 |
|---|---|---|
| `loopback` | 只接 127.0.0.1 | 默认。只有手机上的程序能用 |
| `lan` | 0.0.0.0 | 同网段可访问。打开开关时会明确提示「同网段的人凭这把 Key 就能用」 |

`bind` 的判断只看来源地址，与 MCPBox 全局监听地址无关：全局开在 `0.0.0.0` 时，
`loopback` 的插件仍然只放行本机。

### 8.4 路由脚本的契约

`api/` 下的脚本导出 `handle(ctx)`，用 `ctx.res` 或 `ctx.sse` 把结果写回去：

```js
// api/models.js
export default {
  async handle(ctx) {
    // ctx.req: { method, path, query, headers, body, remote, json() }
    const q = ctx.req.query
    ctx.res.json({ object: "list", data: [{ id: "demo-model" }] })
    // 也可以：ctx.res.text("hi", 200) / ctx.res.respond(body, { status, headers, contentType })
  }
}
```

- `ctx.res.respond(body, opts)`：`body` 是字符串时原样发，其它类型自动 `JSON.stringify`。
  状态码默认 200，可写 `ctx.res.status = 404` 或用 `opts.status`。
- 脚本一次都不写 → 500 `插件脚本没有给出响应`，不会把连接挂在那里。
- 响应正文上限 4 MB；脚本抛异常 → 500，审批被拒 → 403，超时 → 504。
- 方法不在 `methods` 里 → 405，`Allow` 头列出支持的方法。

### 8.5 流式（SSE）

路由声明 `"stream": true` 时 `ctx.sse` 可用（其它路由它是 `null`，误用会直接报错）：

```js
export default {
  async handle(ctx) {
    const up = ctx.http.stream("POST", upstream, {
      method: "POST",
      headers: { Authorization: "Bearer ..." },
      body: JSON.stringify(payload)
    })
    if (up.status !== 200) {
      ctx.res.text(up.text(), up.status)
      return
    }
    ctx.sse.open()
    let line
    while ((line = up.next()) !== null) {
      if (line.startsWith("data: ")) {
        if (!ctx.sse.write(line.slice(6))) break   // false = 客户端已断开
      }
    }
    up.close()
    ctx.sse.close()
  }
}
```

- `ctx.http.stream(...)` 返回 `{ status, headers, next(), text(), close() }`；
  `next()` 同步阻塞读一行（去掉行尾换行），读完返回 `null`。
- `ctx.sse.write` 第一次调用会自动 `open()`；返回 `false` 表示客户端断开，脚本应停止转发。
- `ctx.sse.comment("ping")` 写保活注释帧。
- 单插件同时最多 16 条流式连接，超了在跑脚本之前就回 429。
- 插件停用、卸载、关掉对外服务、换 Key 时，所有流式连接立刻关闭。
- **不提供 WebSocket**：需要双向时用 SSE（服务端 → 客户端）+ 普通 POST（客户端 → 服务端）。

### 8.6 超时

路由脚本的准备时间上限 30 秒，由 JS 引擎的中断机制掐。流式阶段脚本阻塞在
`up.next()` 上属于 Kotlin 的时间，**不计入**这个上限；上游卡住由 HTTP 的读超时兜住。

## 10 插件页面

### 10.1 声明式（一期）

`ui.pages[].blocks` 描述内容，App 用原生 Compose 渲染，自动跟随主题与字号：

| block | 用途 |
|---|---|
| `section` | 标题 + 一段文本 |
| `text` | 一块带底色圆角的文字框，多行，可选等宽 |
| `fields` | 表单，提交时调用脚本的 action |
| `button` | 按钮，带确认（危险操作） |
| `list` | 列表，数据由 action 返回 |
| `key` | 展示插件 Key：复制、轮换、显示掩码 |
| `status` | 一组状态行，例如各渠道的可用性 |
| `progress` | 进度条，用于耗时操作 |
| `log` | 展示插件日志尾部 |

按钮和表单提交走脚本导出的 `actions`：

```js
export const actions = {
  async refresh(ctx) {
    return { blocks: [{ type: "status", items: [{ label: "OpenCode Zen", value: "可用" }] }] }
  }
}
```

action 返回新的 blocks，App 就地替换当前页面内容。这条链路不需要 WebView。

### 10.2 HTML（后期）

`ui.web = "web/index.html"` 时，详情页的「页面」按钮打开一个独立 WebView：

- 只能加载插件目录内的资源；外部链接走系统浏览器。
- 注入一个窄桥：

```js
const r = await window.mcpbox.invoke("refresh")
await window.mcpbox.tool("free_gateway__status", {})
```

- 桥只暴露 `invoke`（插件 action）与 `tool`（工具调用，照常审批），
  不暴露 Java 对象、文件系统与任意 URL 请求。
- 与内置浏览器（AI 控制的那套）是两套独立 WebView，互不共享 cookie 与页面。

### 10.3 插槽（注册到设置页）

插件可以往设置树的指定位置注入一组卡片。内容用声明式描述，App 用现有的 `CardGroup` /
`RowSpec` 渲染，所以主题、动态取色、字号、水波、背景透出都自动正确。

```json
"ui": {
  "slots": [
    {
      "anchor": "settings/network#console",
      "place": "after",
      "rows": [
        { "type": "row", "title": "网关状态", "subtitle": "8 个模型可用", "action": "status", "page": "dashboard" },
        { "type": "switch", "setting": "enabled", "title": "对外提供服务" },
        { "type": "text", "text": "首次使用请先在「插件」页复制 Key。" }
      ]
    }
  ]
}
```

**锚点。** 页面级是 `settings/<页>`，分区级是 `settings/<页>#<分区>`：

| 锚点 | 位置 |
|---|---|
| `settings/appearance` | 外观与语言 |
| `settings/appearance#theme` / `#language` / `#interaction` | 主题 / 语言 / 交互 |
| `settings/appearance/wallpaper` | 背景（预览 / 背景 / 外观） |
| `settings/appearance/bars` | 顶栏底栏 |
| `settings/appearance/ball` / `#icon` / `#langpack` | 悬浮球 / 图标 / 语言包 |
| `settings/network` | 网络与访问 |
| `settings/network#network` / `#console` | 网络 / 网页控制台 |
| `settings/browser` | 浏览器 |
| `settings/browser#security` / `#page` / `#search` / `#identity` | 安全 / 页面 / 搜索 / 身份与登录态 |
| `settings/background` / `backup` / `stats` / `about` | 同名页面 |

分区 id 要在代码里登记成常量表；新增设置页或分区时同步登记，否则插件插不进去。

**不允许插的锚点。**

- `settings/tools`（工具管理）、`settings/memory`（记忆库）——整页排除
- 初始引导（不在设置树里）
- 关于页的「彩蛋 / 开发者模式」分区：技术上未禁，但插件插进去会破坏彩蛋的隐蔽性，安装预览里会提示

**插槽专用 block。**

| block | 说明 |
|---|---|
| `row` | 一行：标题 + 副标题 + 动作 |
| `switch` | 开关，`setting` 指向插件自己的一个 boolean 设置项 |
| `text` | 一段文字框 |

`row` 的动作只有三种：

| 动作 | 效果 |
|---|---|
| `page` | 跳进插件自己的页面 |
| `action` | 执行插件的 action，可带进度 |
| `copy` | 复制一段文本（网关地址、Key 之类） |

**成组规则。**

- 一个插件在一个锚点最多一组。
- 默认**单独成组**：在该分区下方新开一个 `CardGroup`，组标签是「插件 · <插件名>」。
  这样插件停用后整组消失，不留空洞。
- 想在组标签里加一个「插件」标记（`OutlineTag`），让来源一眼可见。

**开关必须标明来源。** 插件不能插会改 App 行为的开关——设置页里的开关现在都对应一个真实配置项，
混进插件的开关，用户分不清哪个是真的。`switch` 只能绑插件自己的 boolean 设置项，
渲染时副标题自动前置「插件设置 · 」，组标签也带插件名。

**刷新。** 插槽内容是动态的（action 返回值会变），不能只靠 `revision`：
`PluginHost` 为每个插件维护一个 `pluginRev`，action 执行完递增，插件卡片以它为 `remember` 的 key。

**三个工程坑，接插槽的设置页都要处理。**

1. **预见式返回的预览层**：`behind` 会渲染上一页的第二个实例，那一页如果有插件卡片就得再渲染一遍。
   否则拖动时看到的是没有卡片的那一页，松手才跳出来。滚动位置同理，要提到宿主共用
   （`SettingsScreen` 里已有先例）。
2. **滚动位置**：卡片高度随内容变化，同一份 `ScrollState` 在两处用时要注意别把位置算乱。
3. **背景透出**：卡片必须走 `cardColor(...)`，否则开了自定义背景时是一块不透明补丁。

**加载顺序。** 插件卡片在页面组合时按锚点收集，排序规则：先按 `place`（before / after），
同位置按插件 id 字典序，保证每次渲染顺序稳定。

## 11 后台任务

由已有的前台服务 `McpService` 托管一个 `PluginScheduler`：

| 来源 | 声明 | 触发 |
|---|---|---|
| 定时 | `"interval": "30m"`（`s`/`m`/`h`，最小 1m，上限 24h） | 服务运行期间按间隔执行 |
| 启动 | `"events": ["startup"]` | App 启动并启用了插件时执行一次 |
| 文件变化 | `"events": ["file.changed"]` + `"watch": ["/sdcard/Download"]` | FileObserver，路径必须先命中允许目录 |
| 工具调用后 | `"events": ["tool.called"]` + `"filter": ["write_file"]` | 指定工具成功执行后 |

```js
export function onEvent(ctx) {
  ctx.log("info", `收到事件：${ctx.event.type}`)
}
```

约束：

- 单次执行超时与工具相同；超时算失败。
- 失败后按 1m / 5m / 15m 退避；连续 3 次失败自动停用插件并在列表标红，用户手动重新启用才恢复。
- 定时任务在 App 进程被杀后不会自行拉起；「常驻」只指前台服务在跑的时候。
- 文件监听只在服务运行期间生效，注销与重启由调度器统一管理。

## 12 权限模型

### 12.1 权限键

| 键 | 新增 | 默认 | 覆盖 |
|---|---|---|---|
| `fs.read` | 否 | 允许 | `ctx.fs.read/list` |
| `fs.write` | 否 | 询问 | `ctx.fs.write`、写 `data/` |
| `fs.delete` | 否 | 询问 | `ctx.fs.remove` |
| `shell.exec` | 否 | 询问 | `ctx.shell.run` |
| `network` | **是** | 询问 | `ctx.http.*` |
| `http.serve` | **是** | 安装时授权 | `http.routes`，对外开端口 |
| `system.info` | 否 | 允许 | 只读设备信息 |
| `browser.control` | 否 | 询问 | 预留 |
| `ui.control` | 否 | 询问 | 预留 |

### 12.2 工具类：逐次审批

插件声明的 `permissions` 是安装时的告知，不是授权本身。每次 host API 调用仍走
`PermissionStore.decide` + `ApprovalCenter`。审批请求里带上插件来源：

```
工具    hello_weather_forecast
插件    天气小助手 1.0.0
操作    访问网络 api.example.com
```

### 12.3 `network` 按网站记住

模型网关每发一个请求就弹窗是不可用的，所以 `network` 的「始终允许」落成一条
**网站规则**——和命令前缀规则同一套机制（`Rule(type = "domain", pattern = "api.example.com")`）：

- 匹配的是主机名，不是完整 URL。精确规则 `api.example.com` 不放行 `x.api.example.com`。
- 通配只支持前缀形式：`*.example.com`，它放行 `example.com` 自己和下面所有子域名。
- 入口在「权限 → 插件联网」，可以逐条改允许 / 拒绝、停用、删除；
  **没有「添加」**——这类规则只从审批弹窗的「始终允许 / 始终拒绝」长出来，省得手填错。
- 工具调用与服务请求共用这套规则，所以网关装上后第一次请求问一次，之后不再问。
- 重定向的每一跳都重新过一遍域名规则，不能借一个已批准的域名 302 到别处去。

### 12.4 服务类：安装授权 + Key

- `http.serve` 不能逐次审批，判定只有两档：安装/启用时用户点同意 → 放行；否则插件不能开路由。
- 开启 `lan` 绑定要额外确认一次，文案写明「同网段设备凭 Key 可访问」。
- 插件停用、Key 轮换、服务停止时，所有打开的 SSE 连接立即关闭。

### 12.5 不信任的地方

- 插件脚本拿不到 `Context`、`SharedPreferences`、Java 类；只能通过 `ctx`。
- 不允许反射；Python 侧关闭 `java` 模块导入。
- 插件目录只允许通过安装流程写入，运行期不能改自己的脚本。
- 插件路由只能返回自己声明的路径，不能把请求转给内置路由（防止绕过别的插件的校验）。
- 插件不能往设置页插会改 App 行为的开关；`switch` 只能绑插件自己的设置项。
- 插件不能占用 `settings/tools`、`settings/memory` 两个锚点。

## 13 安装、升级、卸载

### 13.1 安装

- 入口：插件列表页右上角「导入」，选一个 `.zip`（或 `.mcpbox-plugin`，同一个格式）。
- 校验顺序：zip 结构 → manifest 语法 → 字段合法性 → 保留路径冲突 → 工具名冲突 →
  路径穿越 → 大小上限。任何一步失败都不落盘（与整目录上传的「先校验、再审批、最后写盘」一致）。
- 上限：解压后 20MB、文件数 500。
- 安装预览：名称、版本、作者、说明、声明权限、工具数、**将要占用的路由**
  （例如 `/v1/models`、`/v1/chat/completions`）。占了根级路径的插件要显式标出来。
- 安装后默认停用，用户点「启用」才注册工具与路由。

### 13.2 升级

- 版本号必须大于当前版本；「强制覆盖」需二次确认。
- 保留 `config.json` 与 `data/`；脚本整目录替换。Key 保留，避免已配置的客户端全部失效。
- 升级后自动停用，需要用户重新启用（避免新版本静默拿到旧授权）。

### 13.3 卸载

- 二次确认，列出将删除的目录。
- 可选保留数据：`data/` 移到 `files/plugin-data/<id>/`，重装时自动接回。
- 卸载时先关闭路由与 SSE 连接，再删目录。
- 内置插件 `my.tools` 不能卸载。

## 16 两个目标场景的设计

### 16.1 手机上的免费模型网关

**范围。** 第一阶段只接匿名免费通道：OpenCode Zen 网关、Kilo AI 公共网关。这两类不需要
账号或 Key。要 GitHub 登录校验的 EAC 渠道、要各家登录态的账号渠道，后续单独做。

**对外接口。**

| 路由 | 方法 | 说明 |
|---|---|---|
| `/v1/models` | GET | 返回当前可用模型，OpenAI 格式 |
| `/v1/chat/completions` | POST | 流式与非流式 |

Anthropic 的 `/v1/messages` 等到有客户端明确需要再加。

**客户端配置。**

```
Base URL   http://127.0.0.1:8720/v1
API Key    sk-<插件生成的 Key>
Model      从 /v1/models 里选
```

监听设 `lan` 时把 `127.0.0.1` 换成本机局域网地址。

**渠道探测。** 启动时探一次，之后按 `probe_minutes` 定时探；结果反映在 `/v1/models` 与
插件页的状态区块里。探测失败不影响已缓存的模型列表，只标记该渠道不可用。

**已知风险，写进插件说明。**

- 匿名通道的可用性由上游决定，随时可能限流或下线。
- 请求内容会经过第三方网关，不适合发送敏感数据。
- 一个渠道的模型集合会变，客户端缓存的模型列表要能手动刷新。

**移植要点。** 上游渠道适配器是纯 JS（拼请求 + 解析 SSE），可以搬；缺的是 Node 的
`fetch` / `http`，由 `ctx.http` 补上。账号类渠道要凭据存储与登录流程，单独排期。

### 16.2 电脑与手机之间的文件桥

分工：手机侧是 MCPBox 插件（提供 API），电脑侧是一个独立的 dsh 插件（Node / TypeScript，
单独仓库），在 dsh 里做侧边栏面板。两边之间是普通 HTTP + SSE，不依赖 MCP 协议，
所以别的工具也能用同一套接口。

**手机侧接口。**

| 路由 | 方法 | 说明 |
|---|---|---|
| `/x/files/api/list?path=` | GET | 列目录，返回名称、大小、修改时间、是否目录 |
| `/x/files/api/stat?path=` | GET | 单个路径的信息 |
| `/x/files/api/raw?path=` | GET | 读文件，支持 `Range`，图片直接返回 |
| `/x/files/api/raw?path=` | PUT | 写文件（电脑传到手机走这条） |
| `/x/files/api/events` | GET | SSE，推送文件变化（增删改） |

- 路径语义与 MCP 工具一致，仍走 `PathSandbox`：只能碰允许目录里的东西。
- 鉴权用插件 Key；监听 `loopback` 时电脑连不上，所以这个插件默认 `lan`，
  并强制要求先确认「同网段凭 Key 可访问」。
- SSE 事件带节流（同一路径 500ms 内合并），避免大目录写入时刷屏。

**电脑侧面板要做的事。**

- 文件树 + 预览（文本与图片）。
- 引用：把文件内容作为附件塞进当前对话。
- 编辑：改完 PUT 回去，冲突时以手机文件的修改时间为准并提示。
- 上传：把电脑上的文件拖进来 → PUT 到手机。
- 变化：订阅 SSE，外部改动时刷新对应目录。

**传输。** 局域网直连；不在同一网段时走 Tailscale。走公网必须开 HTTPS 或至少换一把
一次性 Key，这一条写在插件说明里，不默认放开。

**和现有能力的边界。** 电脑上的 dsh 作为 MCP 客户端直连 `http://手机IP:8720/mcp`
已经能读写手机文件，但那是「AI 主动调工具」；这个面板要的是「文件出现在界面里」。
另外内置 SSH/SFTP 也能让电脑挂载手机目录，零插件；插件方案的额外价值只在 dsh 内的
面板体验与实时同步。

### 17.1 P1 的落地情况

已实现的部分与本文档的偏差，记录在这里好让后面几期知道现状：

- **引擎**：`quickjs-kt` 1.0.15（`io.github.dokar3:quickjs-kt`）。选 1.0.15 而不是最新版，是因为
  1.0.16 起 AAR 要求 `compileSdk 37`，而项目是 36；1.0.15 要求 36，正好。
  它用 Kotlin 2.4 发布，项目编译器是 2.1，所以 app 模块开了 `-Xskip-metadata-version-check`。
- **每次调用新建一个 QuickJs 实例**，跑完即关：插件之间不共享全局状态，一个插件玩坏运行时也影响不到下一个。
  工具调用频率低，这点开销可以接受。
- **脚本返回值**：字符串原样；`null` / `undefined` → 空；其它对象 → JSON 文本。
  另外宽容一点：脚本直接 `export default async function (ctx) {...}` 也认，不当成报错。
- **`ctx.http.*` 在 P1 明确报「这个版本还不支持网络访问」**，不糊一个没有权限检查的实现。
  P2 已经补上：走 `network` 权限 + 网站规则 + 审批，工具脚本和路由脚本共用同一套。
- **相对路径只能落在插件自己的 `data/`**（不审批），绝对路径走 `PathSandbox` + 权限矩阵。
- **服务类插件的 Key 在安装时就生成**，但路由在 P2 才真正分派。

### 17.2 P2 的落地情况

- **网络客户端用 `HttpURLConnection`**，不引 OkHttp：mcpcore 是纯 JVM，Android 和 harness 两边都要能跑。
  代价是 `PATCH` 要反射改内部字段，JDK 17 上会被模块系统拦住 —— 那种情况如实报
  「当前系统不支持 PATCH，请改用 POST」，不偷偷改成 POST。
- **响应正文上限 4 MB**，超了截断并置 `truncated`；重定向最多 3 跳，每跳重新过域名规则。
- **`window.Ki` 之外的东西一概不暴露**：路由脚本拿到的 `ctx.req.body` 是字符串，
  要对象自己 `ctx.req.json()`；`ctx.res.respond` 的对象参数在 JS 侧就 `JSON.stringify` 掉了。
- **不走 `checkAuth`**：插件路径在 `dispatch` 里跳过网页登录与令牌校验，用自己的 Key；
  但全局「仅本机访问」仍然拦在前面。
- **`http.serve` 没有做成 `PermKey` 里的三态开关**：它是每个插件独立的授权位（`__httpGranted`），
  因为「允许某个插件对外开端口」不能是全局一刀切。权限页里只有 `network` 这一项。
- **网站规则只从审批弹窗长出来**：规则页里能改允许/拒绝、停用、删除，不提供「手动添加」。
- **流式用同步 `next()` 而不是 `for await`**：脚本里 `while ((line = up.next()) !== null)`
  比给 JS 引擎接一套异步迭代器稳，出错时也更好定位。
- **路由超时不覆盖流式阶段**：`runRoute` 不加 coroutine 超时，只靠 JS 引擎的中断机制管脚本计算时间；
  上游卡住由 HTTP 读超时兜住。工具调用仍然保留外层超时（`evaluationTimeout + 5 秒`）。
- **插件页目前是最小版**：列出已装的、开关对外服务、看/复制/轮换 Key。
  导入、卸载、设置项、日志留给 P3。

## 18 待定

1. **AI 能否自己装插件**：自定义工具允许 AI 创建，插件是否也给一个 `install_plugin` 工具？
   给的话 AI 能装一整包代码，还能占用 HTTP 路由，风险比一条命令大一个量级。
2. **Python 是否真的要做**：Chaquopy 会让 APK 涨到十几 MB，且构建链多一个 Gradle 插件。
   如果两个目标场景都在 JS 能覆盖的范围，P7 可以砍掉。
3. **插件分发**：一期只支持本地导入；是否做一个 GitHub 仓库作为索引，从 URL 安装并检查更新。
4. **网关是否支持 Anthropic 格式**：`/v1/messages` 要不要一起做，取决于你实际用的客户端。
5. **文件桥的冲突处理**：mtime 冲突时是覆盖、另存、还是拒绝，需要在电脑侧插件里定。
