# 02 · 权限与审批

[← 返回 README](../README.md) ｜ [English](en/02-permissions.md)

MCPBox 的默认哲学是：**AI 能干什么，由你在手机上决定**。拦截发生在服务端（权限矩阵 + 规则 + 单工具策略），
不依赖客户端自觉 —— 客户端可以是任意一个 MCP 客户端。

## 权限矩阵：9 个权限键 × 三态

每个权限键有三种取值：**允许** / **询问** / **拒绝**。

| 权限键 | 默认 | 管什么 |
|---|---|---|
| `fs.read` | 允许 | 读文件、列目录、看图、搜索、看回收站 |
| `fs.write` | 询问 | 写入、修改、新建、复制、移动、还原回收站文件 |
| `fs.delete` | 询问 | 删除文件或目录、清空回收站 |
| `shell.exec` | 询问 | AI 执行命令、自定义工具（用户自己在终端敲的不算） |
| `tools.manage` | 询问 | 新建 / 修改 / 删除自定义工具、管理工具包 |
| `ui.control` | 询问 | 控制屏幕：截屏、读界面结构、点击、滑动、输入（需 Root / Shizuku） |
| `browser.control` | 询问 | 内置浏览器：打开网页、点击、填表、执行脚本、读写 cookie（默认**每个动作都问**） |
| `system.info` | 允许 | 设备信息、存储信息、服务器状态、获取令牌 |
| `memory` | 允许 | 记忆库的读写（关掉总开关后记忆工具直接从 `tools/list` 消失） |

在 App 的「**权限**」页最上面可以一键切换**预设会话**：

| 预设 | 效果 |
|---|---|
| 全部允许 | 9 个开关都设为「允许」，AI 不再被打断 |
| 全部拒绝 | 9 个开关都设为「拒绝」，AI 只能读服务器状态 |
| 全部询问 | 9 个开关都设为「询问」，每个敏感动作都弹窗（最安全） |
| 自定义 | 解锁，逐个调 9 个开关 |

- 选前三个时会**锁住**下面的开关（整行不可点），避免出现「写着全部允许、其实写删是询问」这种看不懂的状态。
- 切到固定预设之前，App 会**先把你当前那份自定义设置存下来**；之后再切回「自定义」原样恢复，调过的不会被抹掉。

## 单工具权限四态

除了全局矩阵，**每个工具**还能单独设权限（设置 → 工具管理）：

| 取值 | 含义 |
|---|---|
| 跟随（默认） | 按上面的全局权限矩阵走 |
| 允许 | 这个工具的所有操作直接放行，不弹审批 |
| 询问 | **无视全局矩阵**，这个工具每次调用都弹窗问你一次 |
| 拒绝 | 无论全局怎么设，一律拒绝 |

- 工具还可以被**整体禁用** —— 禁用后它不再出现在 `tools/list` 里。
- 出厂就带单独策略的工具只有一个：`get_token`（默认「询问」，因为它能把访问令牌交出去）。
- 在「询问」触发的弹窗里点「始终允许 / 始终拒绝」，记住的是**这个工具本身**，不会改动全局权限开关。

## 规则：比开关更细的一层

规则可以覆盖开关的判定（两种规则都放在 **设置 → 终端与命令** 里，各自一个子页）：

| 规则 | 匹配方式 | 例子 |
|---|---|---|
| **路径规则** | 最长前缀优先 | 给 `/data/data/me.rerere.rikkahub/` 单独开「允许写」，不必把 `fs.write` 全局放开 |
| **命令规则** | 前缀 / 完全 / 正则，按顺序**首条命中**即生效 | `pm list packages` 前缀 → 允许；`rm -rf` 正则 → 拒绝 |

在审批弹窗上点「始终允许 / 始终拒绝」时，MCPBox 会**自动生成对应规则**，之后同类操作不再打扰你。
规则条数会显示在设置页的入口行上（如「路径规则 · 3 条」）。

## 审批：悬浮窗 / 通知栏

| 设置项 | 默认 | 说明 |
|---|---|---|
| 审批方式 | **悬浮窗** | 顶层悬浮窗浮在所有 App 之上，四个按钮：允许一次 / 始终允许 / 拒绝 / 始终拒绝 |
| 审批方式 = 通知栏 | — | 每条审批一个通知，动作按钮直接在通知里点；正文会带「还有 N 条待审批」 |
| 仅本机访问 / 网页控制台 | — | 网页控制台里也能处理审批 |

- 通知栏模式**永远不弹悬浮窗**（哪怕有悬浮窗权限）；悬浮窗模式**没有权限时仍会自动退回通知栏**，否则请求没人看得见。
- 审批请求被拒绝时，工具会返回明确错误并提示「用户可在 App 的权限页调整该权限」——**被拒绝后不要反复重试**。

## 超时（两处都可以关掉）

| 设置项 | 默认 | 可调范围 | 不限时后 |
|---|---|---|---|
| 审批超时 | **120 秒**（超时自动拒绝） | 15–600 秒滑杆 | 弹窗不会自动消失，AI 一直等你答复（值存 0） |
| 命令默认超时 | **60 秒** | 10–300 秒滑杆 | 命令一直跑到自己结束，不会中途被掐断 |

- 两个「不限时」开关在 **设置 → 安全与审批**（审批）与 **设置 → 终端与命令**（命令）。
- 打开不限时前用的秒数会被记住，关掉开关时原样恢复。
- `run_shell` 和自定义工具的 `timeoutMs` 参数同样支持 `0 = 不限制`。

## 应用私有目录

应用自身读不到别家私有目录，开启后会**经 root / Shizuku 转发**：

- 三档：**禁止**（默认）/ **只读** / **可读写**
- 覆盖范围：`/data/data`、`/data/user/0`、`/data/user_de/0`、`/data/local/tmp`、`/data/app`、`/data/misc`、`/data/system`、`/data/adb`
- 只读模式下写 / 删会被直接拒绝；想只放开某一个应用，用路径规则单独设置
- Android 15+ 的 mount namespace 隔离会让 root 也「看不全」应用数据，本项目会自动探测 `su -mm` / `su -M` 进入 global namespace

权限页里还有「**允许访问的目录**」—— 这是文件沙箱的根目录白名单，只有这些目录下的路径能被工具访问，
可以添加常用目录（如 `/storage/emulated/0/xtt`）。
